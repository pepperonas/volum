# Security Policy

## Reporting a vulnerability

Please report security issues privately through GitHub's **Report a vulnerability**
button on the Security tab of this repository, rather than opening a public issue.

Include what you did, what happened, and what you expected. A proof of concept helps
but is not required.

## Threat model

VOLUM runs locally and processes files that arrive from outside the application.
The following are treated as **untrusted input**:

- Images supplied by the user or dragged in from anywhere.
- 3D files opened for inspection or validation.
- Model archives downloaded from a model host.
- Project directories opened from disk.

Accordingly the engine enforces file size limits, validates types by content rather
than by extension, stores uploads under generated identifiers instead of user-supplied
names, rejects path traversal, runs model inference in a separate subprocess with a
timeout and a working cancellation path, and cleans up temporary directories.

## Local engine interface

The Python engine listens on `127.0.0.1` only, on an ephemeral port, and requires a
per-session bearer token generated by the desktop shell. It is never bound to a
non-loopback interface and never uses a fixed port. If you find a way to reach it
without the token, that is a vulnerability — please report it.

## What is out of scope

- The content of generated 3D assets. Generation models invent unseen geometry; that is
  the nature of the technology, not a security flaw.
- Vulnerabilities in third-party model weights or their upstream repositories. Report
  those upstream; tell us too, so we can gate the model in the Model Manager.

## Privacy

VOLUM performs no telemetry, analytics, or remote inference. Network access is used only
to download model weights you explicitly request. See `docs/privacy.md`.
